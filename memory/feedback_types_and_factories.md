型エイリアスには Python 3.13 の `type RGB = ...` 構文を使う。データクラスの生成処理は `@classmethod` のファクトリへ置き、インスタンスのデータを操作する処理はそのクラスのメソッドへ寄せる。

巨大な関数・メソッドに複数の責務を集めず、変更理由とデータの所有者が明瞭な単位に分ける。再利用できる同じ処理は共通化する。行数だけを理由に分割したり、単発の用途に汎用フレームワークを設けたりしない。

**Why:** 2026-09-13 にユーザーから、C の構造体と外部関数のような構成を Python に持ち込まず、クラスのメソッドを積極的に使うよう指示された。人間向けの慣習だけでなく、今後 Codex が理解して安全に変更できる構成を重視する。

**How to apply:** 生成・変換・検証・更新の所有者を先に決める。Blender RNA の状態は専用の properties 層に集約し、operator は操作の入口、UI は表示を担当する。

2026-09-13 の追加指示では、**Blender の UI 操作で得る結果を保てるなら、Python API・内部構造の破壊的変更を許可**された。UI 自体も操作性が向上するなら変更してよい。旧関数名・import 経路・不要な操作系を守るための互換ラッパーは残さず、呼び出し側とテストを新しい所有者へ移す。後方互換性そのものを設計の目的にしない。
